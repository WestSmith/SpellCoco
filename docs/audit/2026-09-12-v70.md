**SpellCoco audit — September 12, 2026**

Audited [WestSmith/SpellCoco](https://github.com/WestSmith/SpellCoco) at [106203a463eefc8254c631fc240614c452896b91](https://github.com/WestSmith/SpellCoco/commit/106203a463eefc8254c631fc240614c452896b91), the v70 `main` revision retrieved for this audit. The review found **13 actionable issues: three high priority, nine medium priority, and one low priority**. The highest priorities are preventing online state rollback, preserving unacknowledged moves across refreshes, and separating client messages from server messages.

The audit covered the inline application, relay Worker, service worker, manifest, repository checks, and documentation. Thirteen deterministic scenarios reproduced defects using the actual repository JavaScript with DOM, timer, socket, and storage test doubles. A localhost browser session also verified ordinary scoring and turn advancement, the disabled cloud-assist submission path, and missing keyboard access to tiles. A normal “BE” play scored five points and advanced the turn.

The repository's [checks workflow](https://github.com/WestSmith/SpellCoco/actions/runs/34682285620) and [Pages deployment](https://github.com/WestSmith/SpellCoco/actions/runs/34682285148) were successful. I independently passed JavaScript syntax checks, manifest/icon checks, and version/changelog consistency checks. The repository had no open issues or PRs at inspection time. These static checks do not exercise the failures below.

**Status of this draft proposal**

This document records the original v70 audit, before the proposed fixes.
Findings **3, 4, 5, 6, 7, 8, 11, 12 and 13** have proposed code changes in
this branch. Findings **1, 2, 9 and 10 remain unfixed**; see the
[review handoff and designs](proposed-follow-ups.md).

Read-only inspection also confirmed the four Worker-specific defect scenarios
in a downloaded deployed SpellCoco Worker module, executed locally with test
doubles. No production room or Cloudflare configuration was changed. Credentials
and private deployment metadata are excluded from this repository report.

**Findings, in recommended order**

1. **[P1] Replayed or stale snapshots overwrite newer game state.** The Worker checks the current seat, then stores the incoming full snapshot; it echoes `q` without recording processed operations or checking a state revision. If A's move lands but its acknowledgement is lost, B can finish the next turn while A is disconnected. When A reconnects, the replay is accepted because it is A's turn again. Reproduction 1 rolled the room from round 2 back to round 1 and erased B's 20 points. Reproduction 2 demonstrated the same missing concurrency check for Coco Attack: an in-flight selection snapshot erased the attack marker and restored the attacker's spent treats. [Worker turn check and write](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/worker/src/index.js#L171-L188), [client replay](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/index.html#L2806-L2814).

   **Fix:** Give each match an ID, each accepted state a monotonic revision, and each operation a persistent unique ID. Atomically reject stale revisions and acknowledge duplicate operations without applying them again. Coco Attack must participate in that revision scheme. Selection updates should carry only selection data, rather than replacing scores, treats, timers, and history.

2. **[P1] An offline move disappears if the page refreshes before acknowledgement.** `pendingMove` and `pendingStart` exist only in memory, while `saveGameState()` explicitly skips async games. A player can submit while disconnected, receive the message that the move is safe, then lose that move when the browser refreshes or discards the tab. Reproduction 10 confirmed a 30-point pending move with no persistent game payload. [Pending move](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/index.html#L2787-L2809), [async save exclusion](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/index.html#L3992-L3994).

   **Fix:** Persist pending operations before reporting them as saved, restore them before reconnecting, and remove them only after a matching authoritative acknowledgement. Key them by room, match, and player. Implement this together with finding 1 so durable retries cannot overwrite newer turns.

3. **[P1] A seated player can forge server messages through the relay side channel.** An unrecognized `__a` operation falls through to unrestricted forwarding. A player can send server-only operations such as `state`, `welcome`, `moveok`, or `reject` directly to the other client. The recipient processes them as if the server generated them. Reproduction 3 sent a forged `state` from the non-active seat: the other socket received a score of 99,999 while room storage still held zero. This requires access to a room and a seat; it is not evidence of unauthenticated access to arbitrary rooms. [Dispatcher fallthrough](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/worker/src/index.js#L102-L115), [client message handling](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/index.html#L3071-L3113).

   **Fix:** Return or reject after handling the reserved `__a` namespace. Explicitly allowlist and validate side-channel message types. Clients must never be allowed to originate server acknowledgements, roster assignments, or authoritative states.

4. **[P2] Loading a saved game cancels an active Coco countdown.** `Game.fromState()` restores `timeLeft` but forces `cocoTimerActive=false`, creates no timer interval, and only attempts to start attacks with a pending marker. An already-running attack has cleared that marker. Reproduction 4 restored an active attack with 17 seconds remaining as inactive, with no interval. This affects refresh/reconnect and local save restoration. [Restore logic](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/index.html#L4716-L4731).

   **Fix:** Explicitly restore active countdowns after the new game is installed. Define whether time pauses offline or continues against a deadline, and persist the information required for that policy. Avoid resetting a resumed countdown to its original duration.

5. **[P2] An offline Coco attack may never start when the returning player's dictionary is ready.** `fromState()` calls `maybeCocoTimer()` before its caller assigns the new object to global `game`. When the dictionary is ready, `arm()` runs immediately, sees `game !== this`, and returns without scheduling another attempt. Reproduction 5 left the attack pending, with no active countdown or retry. This is distinct from finding 4: the attack has not started yet. [Early call](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/index.html#L4729-L4731), [identity guard and ready path](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/index.html#L5327-L5343).

   **Fix:** Separate restoration from activation: construct the game, assign it, then start pending timers and AI work. Test both warm and cold dictionary loads.

6. **[P2] A hung optional custom-word download prevents the main dictionary from becoming usable.** The main download sets `dictFileLoaded=true` and replaces `DICTIONARY`, but the trie rebuild awaits both `dictOrTimeout` and the unbounded `custP`. If the custom-word request hangs, gameplay continues using the small built-in trie despite the successful full-list status. Reproduction 7 loaded a word into `DICTIONARY` but kept `isValidWord()` false, including after the 20-second timer. [Loading promises](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/index.html#L4591-L4600).

   **Fix:** Bound both requests and allow the base dictionary to become usable independently. Set the ready flag only after the corresponding trie is built. Incorporate optional words later if necessary.

7. **[P2] Importing an ordinary contraction can crash word submission.** Dictionary imports accept any trimmed string of length two or more. The swap solver assumes every trie character exists in `LETTERS` and dereferences `.val` without checking. Reproduction 13 imported `CAN'T` and ran the solver on a board containing C–A–N; it threw `Cannot read properties of undefined (reading 'val')`. Valid submissions invoke that solver before awarding points, so a loaded list can interrupt normal turns. [Import validation](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/index.html#L4602-L4615), [unsafe solver dereference](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/index.html#L2625-L2636), [submission call](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/index.html#L4949-L4957).

   **Fix:** Apply one alphabet/length validation policy to bundled files, manual imports, local additions, and network additions. Report skipped entries to the user and defensively skip unsupported characters in the solver.

8. **[P2] The Submit button prevents the advertised cloud dictionary fallback.** The cloud check is invoked inside `submitWord()` for locally unknown words, but `updateUI()` disables Submit for every such word. There is no alternative keyboard submission handler. Reproduction 6 and the browser check both showed cloud assist enabled, an unknown two-letter selection, and Submit disabled. The separate “add word” path adds or requests consent; it does not perform the automatic dictionary check. [Disabled condition](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/index.html#L5470-L5472), [unreachable fallback](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/index.html#L4940-L4948).

   **Fix:** Allow a syntactically eligible unknown word to be submitted when cloud assist is available, showing a checking state. Bind the response to the match, turn, and selected path so a late lookup cannot submit against a different turn.

9. **[P2] Statistics are not sent by the default async transport.** Async mode receives `stats` messages but never sends them on welcome or peer arrival. All existing sends are in dormant legacy relay/P2P connection paths. Consequently the README's cross-device all-time tracker does not synchronize through the default connection. Reproduction 9 exercised a normal async welcome and observed no stats message. [Async welcome](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/index.html#L3240-L3242), [async receivers](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/index.html#L3143-L3148), [legacy sends](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/index.html#L2933-L2938).

   **Fix:** Add async reconciliation. Prefer syncing completed-match records with unique IDs; taking the maximum of aggregate counters cannot reliably merge distinct matches recorded on different devices.

10. **[P2] A device can miss rematch results because statistics deduplicate by room.** `recordStatsOnce()` uses only the room code as its recorded-result key. The flag is cleared when that client starts or loads a live game. A device that sees the first game's ending, stays unused while the next match is played on another device, and returns only after that match ends still has the old flag. It skips the newer result. Reproduction 8 supplied two different match results under the same room and counted only the first. [Room-level deduplication](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/index.html#L3118-L3124), [live-load reset](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/index.html#L3287-L3292).

    **Fix:** Deduplicate by the match ID from finding 1. Persist completed results separately from the room's current board so older results remain available for reconciliation.

11. **[P2] Server validation accepts states that every client rejects.** `validState()` validates the outer object, array lengths, and serialized length, but not player entries, seat bounds, or tile contents. Reproduction 12 submitted `players:[null,null]` with 25 tiles; the Worker stored it and returned `moveok`, then `Game.fromState()` rejected it. The room is left with an unloadable board until a valid state replaces it. [Worker validator](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/worker/src/index.js#L45-L50), [client validator](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/index.html#L3750-L3754).

    **Fix:** Share an explicit wire schema between client and Worker and validate before persistence. Add transition validation for turns, scores, treat spending, game completion, and new matches; sanitizing strings alone does not establish a legal game state.

12. **[P2] The board cannot be played using a keyboard.** Tiles render as ordinary `div` elements with no focusability, button role, or keyboard handler. Board input is handled through pointer events. Browser inspection confirmed all 25 tiles had `tabIndex=-1` and no role, while player-history buttons were focusable. A screen-reader status announcement does not supply a way to select letters. [Tile rendering](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/index.html#L4666-L4669), [pointer-only input](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/index.html#L4882-L4896).

    **Fix:** Implement keyboard navigation and selection, with names that expose the letter, score, multiplier, and treat. Preserve focus when rendering updates. Give the letter-swap picker equivalent keyboard controls and manage focus when opening or closing dialogs.

13. **[P3] Automatic guest-name collision recovery fails for a full-length name.** `openSeatName()` appends ` 2` and then truncates the result to 14 characters. A 14-character existing name therefore produces the same proposed name. Reproduction 11 returned `ABCDEFGHIJKLMN` unchanged, so the busy-seat fallback cannot select a distinct identity even with a free seat. [Alternative-name construction](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/index.html#L3407-L3410), [name truncation](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/index.html#L3682-L3685).

    **Fix:** Truncate the base before appending a suffix, then verify the result differs from the occupied name. Keep the server and client normalization rules consistent.

**Further improvements**

- Turn the reproduction scenarios into regression tests that assert the corrected behavior. Add a two-client integration suite for disconnect/reconnect, rematches, attack timing, schema rejection, and delayed dictionary responses. The current [workflow](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/.github/workflows/checks.yml) contains no behavioral tests.
- Split the roughly 3,500-line inline script into game rules, transport, persistence, dictionary/solver, and UI modules. Use shared schemas and a documented protocol. Isolate or remove unused networking implementations after deciding whether their compatibility value justifies maintaining them.
- Decouple rendering from persistence and networking. [Every non-quiet `updateUI()`](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/index.html#L5526-L5529) sends a full async snapshot, including ordinary selection changes. Separate ephemeral selection updates from durable moves, throttle them, and avoid rebuilding the whole grid and player cards for each selected letter.
- Make game activation and cleanup explicit. Timer restoration failures show why side effects should happen after assignment. [Old grid listeners remain registered](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/index.html#L5574-L5588), retaining retired game instances; remove listeners or bind them once to the current game. Tie delayed AI work and network responses to the originating match and turn.
- Make async status honest and current. The [My Online Games list](https://github.com/WestSmith/SpellCoco/blob/106203a463eefc8254c631fc240614c452896b91/index.html#L3350-L3395) displays locally remembered turn state without querying the other rooms. Label it “last known” or refresh summaries through a bounded read-only endpoint. Show pending/saved/acknowledged move states separately, and retain useful rejection diagnostics without logging private room links or push subscriptions.

**Evidence and limits**

The original reproductions are preserved in
[`tests/reproduce-v70.mjs`](../../tests/reproduce-v70.mjs); run them against an
unmodified checkout of the audited SHA. Its `REPRODUCED` results demonstrate
bugs. Two scenarios support finding 1; keyboard access was tested separately.

The proposed correctness tests are in `tests/*.test.mjs` and run on every push
and pull request. See [test instructions and manual checks](../../tests/README.md).
They use deterministic DOM, timers, sockets and storage doubles. They are not
live Cloudflare integration tests, push-delivery tests, iPhone suspension tests,
or a complete mobile/assistive-technology compatibility audit. This draft PR
contains repository proposals only; no merge or deployment was performed.
